## 1. 제품 정의

### 1.1 한 줄 정의

> **NFS는 "지금부터 3시간"에 집중하게 만들고, 그 시간이 쌓여 "내 인생이 어디에 쓰였는지"를 보여주는 시간 가계부다.**

### 1.2 이름

**NFS — Not For Sale.** "시간은 돈으로 살 수 없다"를 약자로 가져왔다.

> ⚠️ `NFS`는 개발자 세계에서 Network File System과 충돌한다. 검색·도메인에서 불리하므로
> **항상 `NFS — Not For Sale` 세트로 표기**하고, 온보딩 첫 화면에서 의미를 즉시 해제한다.

### 1.3 핵심 내러티브

온보딩과 최상위 화면에서 반복되는 제품의 한 문장.

> **당신에게 50년이 남았다면, 438,000시간입니다.**
> 잠자는 시간을 빼면 실제로 쓸 수 있는 건 **292,000시간.**
> 이 시간은 어디서도 살 수 없습니다. **Not For Sale.**
> NFS는 그 시간을 무엇에, 누구와 썼는지 기록하는 가계부입니다.

### 1.4 문제의식

| 기존 도구 | 한계 |
|---|---|
| 일반 캘린더 | 하루 전체를 쪼개 넣는 피로도가 높다. **계획만 있고 실행 여부가 남지 않는다** |
| 뽀모도로 앱 | 25분은 잘 재지만 **그 25분이 어디에 쓰였는지 누적되지 않는다** |
| 구글 캘린더 | 일정은 빼곡한데 *"이번 달에 개발/회의/가족에 각각 몇 시간을 썼나"* 를 알 수 없다 |

NFS는 이 셋 사이의 빈자리를 노린다. **실행(타임박싱) → 측정(타이머) → 누적(가계부)** 을 끊김 없이 잇는다.

### 1.5 타겟 사용자

- **1차** — 캘린더를 이미 쓰지만 회고는 못 하는 지식 노동자 (개발자·기획자·디자이너)
- **2차** — 뽀모도로를 쓰지만 기록이 남지 않아 아쉬운 사람
- **공통** — **구글 캘린더 계정을 이미 갖고 있다.** 신규 입력 부담 없이 즉시 통계를 보여줄 수 있다

### 1.6 성공의 정의 (MVP 판정 기준)

| 지표 | 목표 | 이유 |
|---|---|---|
| 가입 후 7일 내 블록 5개 이상 생성 | 40% | 타임박싱이 습관으로 붙었는가 |
| 주간 리포트 재방문율 | 30% | 가계부로서 가치가 있는가 |
| 구글 캘린더 연동률 | 60% | 데이터 소스 확보 = 통계 밀도 |

## 2. 제품 구조

### 2.1 세 개의 화면, 하나의 시간축

NFS는 같은 시간을 세 배율로 본다. 배율이 깊을수록 화면은 어두워지고 좁아진다.

| 화면 | 배율 | 사용자가 여기서 하는 일 |
|---|---|---|
| **리포트** | 년 · 월 · 주 | 내 시간이 어디로 갔는지 돌아본다 |
| **하루** | 오늘 · 지금부터 3시간 | 남은 예산을 보고 블록을 놓는다 |
| **집중** | 블록 하나 | 25분을 실제로 산다 |

이동은 **하단의 떠 있는 탭**으로 한다.

> **깊이 줌(연속 배율 이동)은 MVP에서 제외한다** (확정 · N-013). 탭 내비게이션만으로 완성한 뒤 Phase 2에 얹는다.
> 줌은 제품을 *특별하게* 만들지만 *성립시키지는* 않는다. → `docs/wbs/decision-log.md` N-013

### 2.2 두 종류의 시간

이 제품의 핵심 구분이다. **합산하지 않고 끝까지 나눠서 다룬다.**

| 사용자 표기 | 내부 용어 | 출처 | 성격 |
|---|---|---|---|
| **집중 시간** | 실측 | NFS 블록 타이머 | 타이머가 증명한 시간 |
| **일정 시간** | 신고 | 구글 캘린더 | 일정표가 주장하는 시간 |

이 격차 자체가 제품의 인사이트다 — *"캘린더에선 회의가 1등인데, 실제로 집중한 건 개발이었다."*

### 2.3 하루는 24시간이라는 예산

누구에게나 하루는 24시간이고, NFS는 그 상한을 넘겨 등록할 수 없게 한다.
검증 규칙이 아니라 **화면에 상시 노출되는 대표 UI**다. 상세 규칙은 `03-서비스정책.md` 2장.

### 2.4 주간 마감

한 주가 끝나면 그 주의 캘린더 데이터를 영구히 동결한다.
이유는 성능이 아니라 **통계의 재현성**이다. 상세는 `03-서비스정책.md` 3장.

## 3. MVP 범위

### 3.1 포함

| # | 기능 | 산출 작업 |
|---|---|---|
| 1 | **구글 로그인 단독** (N-014) | B-03, B-10 |
| 2 | 3시간 타임박싱 · 30분 단위 블록 · 태그 필수 | B-04, U-04 |
| 3 | 집중 타이머 (일시정지 / 재개 / 조기 완료) | B-04, F-01, U-05 |
| 4 | **24시간 예산 하드캡 + 잔여 미터** | B-05 |
| 5 | 시간 가계부 (일/주/월/년, 태그별 누적) | B-07, U-03 |
| 6 | 구글 캘린더 **읽기** 연동 + 색상 태그 매핑 | B-10~B-12 |
| 7 | 자정 미완료 블록 자동 정산 · 주간 마감 배치 | B-08, B-09 |
| 8 | 가입 시 1회 과거 백필 (4~8주) | B-13 |

### 3.2 제외 (Phase 2 이후)

| 제외 | 사유 |
|---|---|
| 구글 캘린더 **쓰기** | 스코프 확대가 가입 퍼널을 누른다. 읽기 안정화 후 |
| 깊이 줌 (연속 배율 이동) | 제품을 특별하게 만들지만 성립시키지는 않는다 (N-013) |
| 가용 예산 (수면 시간 반영) | 하드캡만으로 MVP 가치 충족 |
| 사용자 정의 태그 | 통계 축이 가변이 되면 투영 DTO가 무너진다 |
| 라이트 모드 | 별개 팔레트 작업 (N-016) |
| 데스크톱 레이아웃 | 모바일 전용으로 확정 (N-009) |
| 반복 일정 | 타임박싱에 반복 개념이 없다 |
| 공유 · 친구 · 팀 | NFS는 혼자 쓰는 앱 |
| 마감 재개봉(re-open) | 원장 불변성 훼손. 필요하면 역분개 행 추가 방식으로 |
