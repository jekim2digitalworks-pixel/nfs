## 1. 블록 (Block)

### 1.1 생성 규칙

| 항목 | 규칙 |
|---|---|
| 최소 단위 | **30분** |
| 허용 길이 | 30분의 배수 (30 / 60 / 90 / 120 …) |
| 최대 길이 | **180분** (3시간 뷰의 상한) |
| 시작 시각 | 30분 격자에 정렬 (`:00` 또는 `:30`) |
| 카테고리 태그 | **필수.** 태그 없는 블록은 원장에 기록될 수 없으므로 생성 자체를 막는다 |
| 제목 | 선택. 비우면 태그명이 제목이 된다 |
| 배치 | 캘린더 일정과 **겹쳐도 생성 가능** (2.1 규칙 1) |

### 1.2 상태 전이

```
READY ──start──▶ RUNNING ──pause──▶ PAUSED
                    │        ◀─resume─┘
                    │
                    ├── 계획 시간 도달 ──▶ 정산 (NORMAL_COMPLETED)
                    ├── 사용자 완료 ────▶ 정산 (EARLY_FINISHED)
                    ├── 사용자 삭제 ────▶ 정산 (ABANDONED)
                    └── 자정 배치 ─────▶ 정산 (AUTO_SETTLED)
```

정산되면 `ActiveBlock` 행은 **삭제되고** `TimeLog`에 INSERT된다. 되돌릴 수 없다.

### 1.3 집중 시간 계산

- 매초 DB를 갱신하지 않는다. **상태 전이 시점에만** 누적값을 쓴다.
- `현재 집중 시간 = accumulatedFocusSeconds + (now − lastResumedTime)` (RUNNING일 때만 뒷항 가산)
- **기준 시각은 항상 서버 시간이다.** 클라이언트 타이머는 표시 전용.
  → 브라우저 탭이 백그라운드로 가면 `rAF`가 멈춰 클라 누적값이 뒤처진다 (CLAUDE.md §4)

### 1.4 뽀모도로

30분 블록은 뽀모도로 1사이클(집중 25분 + 휴식 5분)과 정확히 맞는다.

| 블록 길이 | 사이클 |
|---|---|
| 30분 | 1회 |
| 60분 | 2회 |
| 90분 | 3회 |

**휴식 5분의 처리** (확정 · N-019)
- 집중 시간(`actualFocusMinutes`)에는 **포함하지 않는다** — 집중하지 않았으므로
- 오늘 예산에서는 **차감한다** — 실제로 흘러간 시간이므로

## 2. 24시간 예산

### 2.1 계산 규칙 4줄 (⭐ 구현 시 이 순서 그대로)

| # | 규칙 | 왜 |
|---|---|---|
| 1 | **배치는 자유** — 캘린더 일정과 겹치는 자리에도 블록 생성 가능 | 구글에 가서 정리하라고 요구하면 그 자리에서 이탈한다 |
| 2 | **계산은 합집합** — 겹친 시각은 몇 개가 겹치든 **1분은 1분으로만** | 단순 합산은 이중 예약이 잦은 사용자를 앱에서 배제한다 |
| 3 | **상한은 1440분** — 합집합 기준 하루 24시간 초과 등록 불가 | 물리 법칙 |
| 4 | **귀속은 실측 우선** — 겹친 구간의 태그는 NFS 블록의 것 | 타이머가 증명한 것이 일정표의 주장을 이긴다 |

> **규칙 2·4의 구간 병합 계산기는 등록 검증과 통계 집계에 동일한 것을 재사용한다.**
> 계산기가 두 벌이면 두 화면의 숫자가 어긋난다. → `budget/DailyTimeBudgetCalculator` (B-05)

### 2.2 계산 대상

합집합에 들어가는 것:
- 오늘 날짜에 귀속된 `TimeLog` 전부
- 진행 중인 `ActiveBlock` 전부 (계획 시간 기준)
- `excludedFromStatistics = false` 인 `ImportedCalendarEvent` 전부

### 2.3 자정을 넘는 블록

- **예산 청구:** 날짜 경계로 **분할**해 각 날짜에 청구 (24시간 캡이 정직하려면 필요)
- **통계 귀속:** **시작한 날**에 전부 귀속 (단순함이 이득)

두 기준이 미세하게 불일치하지만 사용자는 체감하지 못하고, 각 기능은 목적에 최적화된다.

### 2.4 초과 시 동작

등록을 막되, **구글 캘린더를 고치라고 요구하지 않는다.**

1. 무엇이 자리를 차지하는지 목록으로 즉시 제시
2. 각 캘린더 일정에 **"통계에서 빼기" 토글** — NFS 쪽 플래그만 바꾸고 구글 원본은 그대로
3. 특정 캘린더 통째로 제외 / 키워드 자동 제외 규칙

> 우리는 애초에 사용자 일정을 수정할 능력이 없다(읽기 스코프). 이 사실 자체가 연동 심리 장벽을 낮춘다.

### 2.5 노출 원칙

24시간 캡은 실제로는 거의 걸리지 않는다. **걸리지 않는 제약을 상시 설명하지 않는다** (N-010).
- 상시 노출: 남은 시간 숫자 + 미터
- 실제로 막힐 때만 노출: 초과 경고와 정리 안내

## 3. 주간 마감 (Weekly Closing)

### 3.1 원칙

**한 주가 끝나면 그 주의 캘린더 데이터를 더 이상 가져오지 않고 영구히 동결한다.**

### 3.2 상태 흐름

```
[열린 주]  대시보드 열람 → 마지막 동기화 후 N분 경과 시 구글 API 호출
             → imported_calendar_event upsert (이 테이블이 곧 캐시)
             → 화면 = time_log(이번 주 블록) + imported_calendar_event

[마감]     월요일 04:00 배치
             → 지난주 구간 최종 1회 동기화
             → 겹침 차감 계산
             → time_log INSERT (source_type = GOOGLE_CALENDAR)
             → imported_calendar_event 해당 주 DELETE
             → weekly_closing = CLOSED

[마감 후]  구글을 다시 호출하는 코드 경로가 존재하지 않는다
```

### 3.3 세부 규칙

| 항목 | 값 | 이유 |
|---|---|---|
| 주 시작 요일 | **월요일** | — |
| 주 식별자 | **`weekStartDate` (월요일 날짜)** | ISO 연도+주차는 53주차·연말 경계에 함정이 있다 |
| 마감 시각 | **월요일 04:00** | 일요일 밤늦게 일하거나 캘린더를 정리하는 사람에게 유예 |
| 마감 전 알림 | 일요일 중 1회 | 자연스러운 주간 회고 트리거 |
| 재개봉(re-open) | **없음** | 원장 불변성. 수정이 필요하면 역분개 행 추가 방식 (Phase 2) |

### 3.4 동기화 실패 처리

마감 시 구글 호출이 실패하면 **조용히 0시간으로 처리하지 않는다.**
`weekly_closing.calendar_sync_result = FAILED`로 남기고, 그 주 리포트에 *"이 주는 캘린더가 반영되지 않았습니다"* 를 표시한다.

> 주중 내내 `imported_calendar_event`에 쌓아두는 이유가 이것이다. 마감 시점에만 호출하는 설계라면
> 하필 그때 토큰이 만료돼 있을 경우 **그 주 데이터를 영구히 잃는다.**

### 3.5 유일한 예외 — 가입 시 백필

신규 가입자에게 빈 통계 화면을 보여주면 이탈한다.
**가입 시점에 한해 최근 4~8주를 1회 끌어와 즉시 마감 상태로 넣는다.** 이후로는 열린 주를 제외하고 구글을 부르지 않는다.

## 4. 구글 캘린더 연동

### 4.1 파이프 구조

```
읽기 :  구글 ──▶ NFS     열린 주만. 마감되면 중단
쓰기 :  NFS  ──▶ 구글     완료 블록만. 옵트인. (Phase 2)
차단 :  쓸 때 extendedProperties.private 에 NFS 블록 ID를 심고,
        읽을 때 그 표식이 있으면 건너뛴다        ← 에코 루프 방지
```

두 파이프는 서로 만나지 않는다.

### 4.2 읽기 필터 (⭐ 안 거르면 통계가 즉시 망가진다)

| # | 대상 | 처리 | 이유 |
|---|---|---|---|
| 1 | 종일 일정 | 제외 | 하나에 24시간이 꽂힌다 |
| 2 | 공휴일·구독 캘린더 | 제외 | 사용자가 반영할 캘린더를 직접 선택 |
| 3 | 참석 거절(declined)한 일정 | 제외 | 안 간 회의는 내 시간이 아니다 |
| 4 | 8시간 초과 일정 | 제외 | "휴가", "출장" 같은 덩어리 |
| 5 | NFS가 쓴 일정 | 제외 | 에코 루프 차단 |
| 6 | 사용자가 끈 일정 | 제외 | `excludedFromStatistics = true` |
| 7 | 미분류 일정 | **수집** (`UNCATEGORIZED`) | 버리지 말고 "분류 안 된 시간"으로 보여주는 것이 정직 |

### 4.3 태그 매핑 우선순위

1. **구글 이벤트 색상(`colorId`) → CategoryTag** (사용자 설정)
2. 제목 키워드 규칙
3. `UNCATEGORIZED`

> 키워드를 1순위로 두면 *"회의록 정리"* 가 회의로 잡히는 오분류가 계속 난다.
> 색상이 사용자의 명시적 의도에 더 가깝다.

### 4.4 쓰기 (Phase 2)

- 기본은 **읽기 전용 스코프.** 처음부터 쓰기를 요구하면 가입 전환율이 떨어진다
- 집중 완료 화면에서 "캘린더에 남기기"를 처음 누를 때 **증분 권한 요청**
- 우리가 쓴 일정을 사용자가 구글에서 지워도 신경 쓰지 않는다. **원장은 `TimeLog`, 구글은 사본**

## 5. 카테고리 태그

MVP는 **고정 enum 7종 + 미분류**. 사용자 정의 태그를 열면 통계 축이 가변이 되어 집계 쿼리와 화면 DTO가 무너진다.

| enum | 표시 | 색 토큰 |
|---|---|---|
| `DEVELOPMENT` | 개발 | `--dev` |
| `MEETING` | 회의 | `--meet` |
| `STUDY` | 학습 | `--study` |
| `FAMILY` | 가족 | `--family` |
| `HEALTH` | 건강 | `--health` |
| `PERSONAL` | 개인 | `--self` |
| `CHORE` | 잡무 | `--chore` |
| `UNCATEGORIZED` | 미분류 | `--tx3` |

`TimeLog`에는 **이관 시점의 태그를 값으로 복사**한다. 나중에 태그 정책이 바뀌어도 과거 통계가 소급 변경되지 않게 하기 위한 스냅샷이다.

## 6. 시간대 (Timezone)

| 항목 | 값 |
|---|---|
| MVP 기준 | **단일 타임존 `Asia/Seoul`** — 코드가 존을 명시한다 (`packages/domain/time`) |
| 회원별 타임존 | Phase 2 |
| 배치 기준 | 서버 시간 |

> ⚠️ **실행 환경은 UTC다.** Vercel 함수도, GitHub Actions 크론도 UTC로 돈다.
> 존을 명시하지 않으면 자정 정산과 주간 마감이 9시간 — 주간은 **요일까지** — 어긋난다.
> 이 프로젝트의 1순위 예약 버그이며, 배포 체크리스트 1번 항목이다.
>
> 프로세스 `TZ` 고정으로 막던 방식은 서버리스에서 쓸 수 없다.
> **환경이 아니라 코드가 존을 안다** (`개발/01-아키텍처.md` §6.1).
