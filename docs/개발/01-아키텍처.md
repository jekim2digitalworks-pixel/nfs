## 1. 스택

| 층 | 선택 | 비고 |
|---|---|---|
| 언어 / 런타임 | **Java 17** | ✅ N-012 |
| 프레임워크 | **Spring Boot 3.2** | `jakarta.persistence` |
| ORM | Spring Data JPA + **QueryDSL 5.x** | ⚠️ **`jakarta` classifier 필수.** `javax`로 잡으면 Q타입이 생성되지 않는다 |
| 빌드 | **Gradle 8** · **war 패키징** | JSP는 fat jar에서 동작하지 않는다 |
| 뷰 | **JSP + jQuery + Ajax** | 단일 페이지 위주, JSON 응답. TS 번들 없음 |
| DB | **MySQL 8** | ✅ N-015. 로컬도 H2 대신 실제 MySQL을 쓴다 |
| 마이그레이션 | Flyway | `ddl-auto: validate` |
| 배포 | AWS EC2 (Linux) | **TZ `Asia/Seoul` 고정 필수** |

### 1.1 프론트엔드 정책

**MVP는 순수 JSP + jQuery.** TypeScript 번들은 쓰지 않는다.

초기 결정 N-002에서 깊이 줌 카메라를 위해 TS 번들 예외를 허용했으나,
확정 시안이 탭 내비게이션을 채택하면서 MVP에는 카메라가 필요 없어졌다.
**N-013으로 깊이 줌이 Phase 2로 이연되면서 TS 번들 예외도 함께 보류됐다.**

- O-02 스캐폴딩에 `static/ts/` 빌드 파이프라인을 **넣지 않는다**
- Phase 5 착수 시 이 절을 개정하고 N-002를 되살린다

## 2. 패키지 구조

```
com.nfs
├── common/          공통 (응답 래퍼, 예외, 시간 유틸)
├── member/          회원 · 인증 · 세션
├── block/           ⭐ ActiveBlock 생명주기 + 정산
│   ├── domain/          ActiveBlock, BlockStatus
│   ├── service/         ActiveBlockService, BlockSettlementService
│   └── web/             BlockController
├── timelog/         원장
│   ├── domain/          TimeLog, SourceType, CompletionType
│   └── repository/      TimeLogRepository, TimeLogQueryRepository(QueryDSL)
├── budget/          ⭐ 24시간 예산
│   ├── DailyTimeBudgetCalculator
│   └── TimeRange, TimeRangeMerger
├── statistics/      통계 (QueryDSL 투영)
│   ├── dto/             TagStatisticsDto, PeriodSummaryDto …
│   └── service/         StatisticsService
├── google/          구글 캘린더
│   ├── GoogleOAuthService, CalendarSyncService
│   ├── CategoryMappingService, CalendarEventFilter
│   └── domain/          ImportedCalendarEvent
├── closing/         주간 마감
│   ├── domain/          WeeklyClosing, ClosingStatus
│   └── service/         WeeklyClosingService
└── batch/           스케줄러
    ├── DailySettlementJob     (매일 00:05)
    └── WeeklyClosingJob       (월 04:00)
```

**기준:** 기술 계층(controller/service/repository)이 아니라 **도메인**으로 먼저 나눈다.
`budget`과 `block`을 분리한 이유는 예산 계산기가 블록·캘린더·원장을 모두 읽는 **가로지르는 관심사**이기 때문이다.

## 3. 계층 규칙

```
Controller ──▶ Service ──▶ Repository ──▶ DB
     │             │
     │             └─▶ 다른 Service (허용, 단 순환 금지)
     └─▶ DTO 만 반환. 엔티티를 그대로 내보내지 않는다
```

| 규칙 | 이유 |
|---|---|
| 엔티티를 JSON으로 직렬화하지 않는다 | 지연 로딩 폭발 + 스키마가 API 계약이 되어버린다 |
| `@Transactional`은 Service에만 | 트랜잭션 경계를 한 층으로 고정 |
| 조회 전용은 `@Transactional(readOnly = true)` | 더티 체킹 생략 |
| 도메인 규칙은 엔티티 메서드로 | `block.pauseTimer(now)` ✓ / 서비스에서 필드 직접 조작 ✗ |

## 4. 통계 조회 — QueryDSL 직접 투영

```java
// 개념 예시. 엔티티를 가져와 자바에서 가공하지 않는다.
List<TagStatisticsDto> rows = queryFactory
    .select(Projections.constructor(TagStatisticsDto.class,
            timeLog.categoryTag,
            timeLog.sourceType,
            timeLog.actualFocusMinutes.sum()))
    .from(timeLog)
    .where(timeLog.memberId.eq(memberId),
           timeLog.statDate.between(from, to))
    .groupBy(timeLog.categoryTag, timeLog.sourceType)
    .fetch();
```

**왜 투영인가:** 월 단위 통계는 수천 행을 읽는다. 엔티티로 로딩하면 영속성 컨텍스트에 전부 올라가고
GC 압력과 응답 지연이 같이 온다. 화면이 필요한 건 태그·출처·합계 세 컬럼뿐이다.

**집중/일정 분리는 `sourceType`으로 GROUP BY 한다.** 두 번 쿼리하지 않는다.

## 5. 배치

| 잡 | 시각 | 하는 일 | 실패 시 |
|---|---|---|---|
| `DailySettlementJob` | 매일 **00:05** | 전날 `work_date`의 미완료 `ActiveBlock`을 `AUTO_SETTLED`로 정산 | 회원 단위 트랜잭션. 한 명 실패가 전체를 막지 않는다 |
| `WeeklyClosingJob` | **월 04:00** | 지난주 최종 동기화 → 겹침 차감 → `TimeLog` 이관 → 마감 | `calendar_sync_result = FAILED` 기록 후 계속 진행 |

- 구현은 `@Scheduled` + `@Async` 회원 단위 처리로 시작한다. Spring Batch는 과하다
- **단일 인스턴스 전제.** 다중화하면 ShedLock 등 분산 락이 필요하다 (Phase 2)
- 배치는 **멱등해야 한다.** 재실행해도 `TimeLog` UNIQUE가 중복을 막는다

## 6. 시간 처리 (⭐ 사고 다발 지점)

| 규칙 | 내용 |
|---|---|
| 기준 시각 | **항상 서버 시간.** 클라이언트가 보낸 시각을 신뢰하지 않는다 |
| 타임존 | JVM `-Duser.timezone=Asia/Seoul` 고정. **EC2 기본은 UTC다** |
| 타입 | `LocalDateTime` / `LocalDate` (단일 타임존 전제). 회원별 TZ는 Phase 2 |
| 클라 타이머 | **표시 전용.** 재진입·포커스 복귀 시 서버와 재동기화 |
| 현재 시각 주입 | `Clock` 빈으로 주입해 테스트에서 고정 가능하게 |

> `Clock`을 주입하지 않으면 자정 경계·마감 경계 테스트를 쓸 수 없다.
> 이 프로젝트는 시간이 핵심 도메인이라 처음부터 넣는다.

## 7. 예외 · 응답 규약

```json
// 성공
{ "success": true, "data": { ... } }

// 실패
{ "success": false, "error": { "code": "BUDGET_EXCEEDED", "message": "오늘 남은 4시간을 넘습니다", "detail": { "remainingMinutes": 240 } } }
```

| 코드 | 상황 | HTTP |
|---|---|---|
| `BUDGET_EXCEEDED` | 24시간 예산 초과 | 400 |
| `INVALID_BLOCK_LENGTH` | 30분 배수 아님 | 400 |
| `CATEGORY_REQUIRED` | 태그 미지정 | 400 |
| `ILLEGAL_BLOCK_STATE` | 잘못된 상태 전이 | 409 |
| `ALREADY_SETTLED` | 이미 정산됨 | 409 |
| `CALENDAR_SYNC_FAILED` | 구글 호출 실패 | 502 |
| `WEEK_ALREADY_CLOSED` | 마감된 주 수정 시도 | 409 |

**`message`는 사용자에게 그대로 보여줄 수 있는 한국어**로 쓴다. 프론트에서 코드별 문구를 다시 만들지 않는다.

## 8. 보안

| 항목 | 처리 |
|---|---|
| 세션 | 서버 세션 (JSP 전제). `HttpOnly` + `SameSite=Lax` |
| 구글 리프레시 토큰 | 암호화 저장. 연동 해제 시 즉시 파기 |
| 스코프 | 기본 읽기 전용. 쓰기는 증분 권한 요청 (Phase 2) |
| XSS | 사용자 입력이 `innerHTML`로 들어가는 자리 전부 이스케이프 (블록 제목, 캘린더 일정 제목) |
| CSRF | 상태 변경 API에 토큰 필수 |
| 인가 | 모든 조회/변경에 `memberId` 조건 강제. **URL의 id를 신뢰하지 않는다** |

## 9. 배포 체크리스트

1. ⭐ **`-Duser.timezone=Asia/Seoul`** — 안 하면 배치가 9시간 어긋난다
2. `war` 패키징 확인 (JSP 렌더링 검증)
3. Flyway `validate` 통과
4. 구글 OAuth 리다이렉트 URI에 운영 도메인 등록
5. 배치 스케줄 활성화 여부 (단일 인스턴스 확인)
6. DB 커넥션 풀 · 슬로우 쿼리 로그
