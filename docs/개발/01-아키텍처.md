### 1.1 왜 이 조합인가 (트레이드오프)

- **단일 앱**: 배포 대상이 1곳이라 push 한 번으로 화면과 API가 같이 뜬다. 동일 출처라 CORS가 없고 세션 쿠키가 그냥 붙는다. 대신 **NestJS의 DI·파이프·계층 강제를 잃었다** → 규약으로 지킨다 (§3).
- **Prisma**: 스키마에서 타입을 만든다. 복잡한 집계에서 표현력이 약해 §4처럼 **`$queryRaw` 탈출구**를 명시적으로 허용한다.
- **모노레포**: 이 프로젝트 최대 위험은 *"예산 계산기가 서버·클라 두 벌이라 숫자가 어긋난다"* 였다. `packages/domain`을 양쪽이 import하면서 **위험이 구조적으로 사라진다.** 이 이득만은 세 번의 스택 전환에도 흔들리지 않았다.
- **무료 티어의 한계를 알고 쓴다**: 함수 실행시간 상한 · 콜드스타트 · 프로젝트 일시정지. 검증 단계에선 받아들이지만 사용자가 늘면 다시 볼 항목이다 (N-022).

### 2.1 `packages/domain`의 철칙 ⭐

```
1. Next.js · Prisma · React 를 import 하지 않는다.
2. I/O 를 하지 않는다. DB도, 네트워크도, 파일도.
3. '지금'을 스스로 만들지 않는다. now 는 항상 인자로 받는다.
```

3번은 v1.0의 `Clock` 빈 주입과 같은 목적이다. 자정 경계·마감 경계를 테스트하려면 시간을 **바깥에서 밀어 넣을 수 있어야** 한다.

```ts
// ✓ 이렇게
export function calculateDailyBudget(input: BudgetInput, now: DateTime): BudgetResult

// ✗ 이렇게 말고 — 이 함수는 자정 5분 전 상황을 테스트할 수 없다
export function calculateDailyBudget(input: BudgetInput): BudgetResult
```

### 2.2 `server/` 를 왜 따로 두나

NestJS를 버리면서 **"이건 서버 전용"이라고 말해주는 프레임워크가 사라졌다.**
Next.js에서 서버 코드를 클라이언트 컴포넌트가 import하면 번들에 섞여 들어간다 —
**Prisma 커넥션 문자열과 구글 시크릿이 브라우저로 나갈 수 있다는 뜻이다.**

| 방어선 | 수단 |
|---|---|
| 1 | 서버 전용 코드는 전부 `src/server/` 아래로. 경로만 봐도 구분된다 |
| 2 | `src/server/index.ts` 최상단에 **`import 'server-only'`** — 클라이언트에서 import하면 **빌드가 깨진다** |
| 3 | ESLint `no-restricted-imports`로 `components/**` → `server/**` 참조 금지 |

## 3. 계층 규칙

```
Route Handler ──▶ Service ──▶ Repository(Prisma) ──▶ DB
      │              │
      │              ├─▶ 다른 Service (허용, 단 순환 금지)
      │              └─▶ packages/domain (순수 계산)
      └─▶ DTO 만 반환. Prisma 모델을 그대로 내보내지 않는다

Server Component ──▶ Service (⭐ HTTP 없이 직접 호출)
```

| 규칙 | 이유 |
|---|---|
| **Server Component는 자기 API를 fetch 하지 않는다** | 같은 프로세스인데 HTTP를 한 바퀴 도는 건 순수한 낭비다. 서비스 함수를 직접 부른다 |
| Prisma 모델을 그대로 JSON으로 내보내지 않는다 | 스키마가 API 계약이 되어버린다. 컬럼명을 못 바꾸게 된다 |
| 트랜잭션은 Service에서 `prisma.$transaction`으로만 | 트랜잭션 경계를 한 층에 고정 |
| **계산 로직은 Service가 아니라 `packages/domain`에** | 서버·클라가 같은 코드를 쓰게 하는 유일한 방법 |
| 입력 검증은 **Zod 스키마**로 Route Handler 입구에서 | 서비스가 방어 코드로 더러워지지 않는다 |
| 모든 조회/변경에 `memberId` 조건 강제 | §8 참조 |

### 3.1 Route Handler 의 고정 모양

프레임워크가 강제하지 않으므로 **모양을 문서로 고정한다.** 전부 이 형태를 따른다.

```ts
// app/api/blocks/route.ts
import 'server-only';

const CreateBlockSchema = z.object({
    categoryTag: CategoryTagSchema,
    title: z.string().max(100),
    plannedStartTime: z.string().datetime({ local: true }),
    plannedMinutes: z.number().int().min(30).max(180),
    startImmediately: z.boolean(),
});

export async function POST(request: Request): Promise<Response> {
    return withMember(request, async (memberId) => {
        // 1. 입력 파싱 — 여기서 걸러야 서비스가 깨끗해진다
        const rawBody = await request.json();
        const command = CreateBlockSchema.parse(rawBody);

        // 2. 처리 — 판단은 전부 서비스와 도메인이 한다
        const createdBlock = await blockService.createBlock(memberId, command);

        // 3. 결과
        return ok(createdBlock);
    });
}
```

`withMember`가 세션 확인 + 에러 매핑 + `{ success }` 래핑을 한다.
**핸들러가 `{ success: true }`를 손으로 감싸면 언젠가 한 곳이 빠진다.**

#### ⚠️ Next 16 실측 정정 (N-024)

O-02 스캐폴딩을 실제로 돌려 확인한 내용이다. **기억으로 쓰지 말 것.**

| 항목 | 사실 |
|---|---|
| `export const runtime = 'nodejs'` | **쓰지 않는다.** 16에서 기본값이고 Edge는 deprecated — 동봉 문서가 제거하라고 명시한다 |
| `export const dynamic = 'force-dynamic'` | **핸들러마다 쓰지 않는다.** 루트 레이아웃(`app/layout.tsx`)에 한 번만 (§3.3) |
| `cookies()` · `headers()` | **`await` 필수.** 16에서 동기 접근이 완전히 제거됐다 |
| `params` · `searchParams` | **Promise 다.** `const { blockId } = await props.params` |
| 배치 엔드포인트 | `export const maxDuration = 60` 으로 상한을 명시한다 (§5.2) |

```ts
// 세션 가드의 실제 모양
export async function withMember(handler: (memberId: bigint) => Promise<Response>) {
    const cookieStore = await cookies();        // ⚠️ await
    const sessionToken = cookieStore.get('nfs_session')?.value;
    ...
}
```

> 프레임워크 API를 문서에 적기 전에 **`apps/web/node_modules/next/dist/docs/`** 를 먼저 읽는다.
> Next 16이 자기 문서를 동봉하고 *"이건 네가 아는 Next가 아니다"* 라고 경고하는 이유가 이것이다.

### 3.3 동적 렌더는 루트 레이아웃에서 한 번만 ⭐

```ts
// app/layout.tsx
export const dynamic = 'force-dynamic';
```

**NFS는 정적으로 굳혀도 되는 화면이 하나도 없다.** 모든 화면이 '지금'과 로그인한 회원에 의존한다.

이걸 빼면 어떻게 되는지 O-02에서 실제로 재현했다.

```
Route (app)
┌ ○ /          ← nowInAppZone() 을 쓰는 화면이 Static 으로 프리렌더됐다
```

**빌드 시점의 날짜가 박제된 HTML이 배포된다.** 시간이 제품인 앱에서 이건 조용하고 치명적이다.
`await cookies()`로 세션을 읽으면 자동으로 동적이 되긴 하지만, 그건 *우연히 그렇게 되는* 방어다.
의도를 한 곳에 적어둔다.

### 3.2 도메인 규칙은 어디에 두나

v1.0에서는 *"도메인 규칙은 엔티티 메서드로 (`block.pauseTimer(now)`)"* 였다.
**Prisma 모델은 평범한 객체라 메서드를 가질 수 없다.** 그래서 위치가 바뀐다.

```ts
// packages/domain/block/transitions.ts — 순수 함수로 옮긴다
export function pauseBlock(block: ActiveBlockSnapshot, now: DateTime): ActiveBlockSnapshot {
    if (block.blockStatus !== 'RUNNING') {
        throw new IllegalBlockStateError(block.blockStatus, 'PAUSED');
    }
    const elapsedSeconds = Math.floor(now.diff(block.lastResumedTime, 'seconds').seconds);
    const accumulatedFocusSeconds = block.accumulatedFocusSeconds + elapsedSeconds;
    return { ...block, blockStatus: 'PAUSED', accumulatedFocusSeconds, lastResumedTime: null };
}
```

**서비스는 이 결과를 받아 저장만 한다.** 상태 전이 판단을 서비스가 하지 않는다 —
그러면 같은 판단이 API와 배치 두 군데에 생기고, 언젠가 한쪽만 고쳐진다.

## 4. 통계 조회 — 집계는 DB에서

**원칙은 v1.0과 같다: 모델을 전부 읽어 앱에서 가공하지 않는다.**
월 단위 통계는 수천 행이다. 화면이 필요한 건 태그·출처·합계 세 컬럼뿐이다.

```ts
// 단순 그룹핑은 Prisma groupBy 로 충분하다
const rows = await prisma.timeLog.groupBy({
    by: ['categoryTag', 'sourceType'],
    where: { memberId: memberId, statDate: { gte: fromDate, lte: toDate } },
    _sum: { actualFocusMinutes: true },
});
```

**집중/일정 분리는 `sourceType`으로 GROUP BY 한다. 두 번 쿼리하지 않는다.**

⚠️ **분을 담는 컬럼은 `actual_focus_minutes` 하나뿐이다.** 별도의 `claimed_minutes` 는 없다.
같은 컬럼이 출처에 따라 다른 것을 뜻한다 — `NFS_BLOCK` 이면 **타이머가 잰 시간**,
`GOOGLE_CALENDAR` 면 **일정이 주장하는 시간**이다.
그래서 두 값을 **절대 그냥 더하지 않는다.** 화면도 끝까지 나눠서 보여준다 (기획 §2.2).

### 4.1 `$queryRaw` 를 허용하는 경우 (⚠️ Postgres 방언)

Prisma `groupBy`는 조건부 합계(`SUM(CASE WHEN …)`)나 기간 버킷팅을 표현하지 못한다.
억지로 Prisma 문법에 맞추다 앱에서 후처리하면 위 원칙을 어기게 된다. 이때는 raw로 간다.

```ts
// 12개월 추이 — 월별 버킷은 DB가 만드는 게 맞다
const monthly = await prisma.$queryRaw<MonthlyRow[]>`
    SELECT to_char(stat_date, 'YYYY-MM') AS "yearMonth",
           SUM(CASE WHEN source_type = 'NFS_BLOCK'       THEN actual_focus_minutes ELSE 0 END) AS "focusMinutes",
           SUM(CASE WHEN source_type = 'GOOGLE_CALENDAR' THEN actual_focus_minutes ELSE 0 END) AS "calendarMinutes"
      FROM time_log
     WHERE member_id = ${memberId} AND stat_date BETWEEN ${fromDate} AND ${toDate}
     GROUP BY 1
     ORDER BY 1`;
```

| 규칙 | 이유 |
|---|---|
| 반드시 **태그드 템플릿** `$queryRaw` | `$queryRawUnsafe`는 문자열 연결이라 SQL 인젝션이 열린다 |
| 반환 타입을 명시(`<MonthlyRow[]>`) | raw는 타입 추론이 없다. 안 쓰면 `any`가 조용히 퍼진다 |
| `WHERE member_id` 를 빼먹지 않는다 | raw에는 자동 스코프가 없다. **여기가 가장 위험한 자리다** |
| ⚠️ **별칭에 큰따옴표** (`AS "yearMonth"`) | Postgres는 따옴표 없는 식별자를 **소문자로 접는다.** MySQL에서는 없던 함정이다 |
| `SUM()` 결과는 `Number()`로 변환 | Postgres `SUM(int)`은 `bigint`로 온다. JSON 직렬화에서 터진다 |

> MySQL → Postgres 전환에서 실제로 바뀐 건 **이 절뿐이다.** `DATE_FORMAT` → `to_char`, 식별자 대소문자, `SUM` 타입.
> 스키마·제약·인덱스는 그대로 유효하다 (`02-데이터모델.md`).

## 5. 배치 — GitHub Actions 크론 (⭐ N-022)

**Vercel에는 상주 프로세스가 없다.** 배치를 앱 안에서 스케줄링할 수 없으므로 **밖에서 밀어 넣는다.**

| 잡 | 시각 (KST) | 크론 (UTC) | 하는 일 |
|---|---|---|---|
| `daily-settlement` | 매일 **00:05** | `5 15 * * *` | 전날 `workDate`의 미완료 `ActiveBlock`을 `AUTO_SETTLED`로 정산 |
| `weekly-closing` | **월 04:00** | `0 19 * * 0` | 지난주 최종 동기화 → 겹침 차감 → `TimeLog` 이관 → 마감 |

```yaml
# .github/workflows/daily-settlement.yml
name: daily-settlement
on:
  schedule:
    - cron: '5 15 * * *'      # ⭐ UTC 15:05 = KST 00:05 (다음 날)
  workflow_dispatch:           # 손으로도 돌릴 수 있게 — 장애 복구용
jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl -fsS -X POST \
            -H "x-cron-secret: ${{ secrets.CRON_SECRET }}" \
            "${{ secrets.APP_URL }}/api/jobs/daily-settlement"
```

⚠️ **주간 마감의 크론이 `* * 0`(일요일)인 이유:** KST 월요일 04:00 = **UTC 일요일 19:00**이다.
요일까지 하루 밀린다. *이 프로젝트가 반복해서 밟는 9시간 함정이 인프라 레벨에서 다시 나타난 것*이므로,
**크론 표현식 옆에 KST 환산을 반드시 주석으로 병기한다.**

### 5.1 엔드포인트 보호

```ts
// app/api/jobs/daily-settlement/route.ts
export async function POST(request: Request): Promise<Response> {
    const providedSecret = request.headers.get('x-cron-secret');
    if (providedSecret !== process.env.CRON_SECRET) {
        // 401 이 아니라 404 — 이런 엔드포인트가 있다는 사실 자체를 알리지 않는다
        return new Response(null, { status: 404 });
    }
    ...
}
```

- 공개 URL에 정산 트리거가 노출되면 **누구나 남의 원장을 정산시킬 수 있다**
- 시크릿은 GitHub Secrets + Vercel 환경변수 양쪽에 같은 값으로 둔다

### 5.2 멱등성과 실행시간

- 배치는 **멱등해야 한다.** 재실행해도 `TimeLog` UNIQUE 제약이 중복을 막는다 (`02-데이터모델.md` §1.1). 크론이 두 번 발화해도 안전하다
- 회원 단위로 순회하며 **한 명씩 트랜잭션.** 전체 배치를 하나의 트랜잭션으로 묶지 않는다
- ⚠️ **함수 실행시간 상한이 있다.** 회원이 늘면 한 번에 다 못 돈다
  → 대응: `export const maxDuration = 60` 으로 상한을 명시하고, 처리 안 된 회원이 남으면 응답에 `hasMore: true`를 담아 워크플로가 **비어질 때까지 재호출**한다. 멱등하므로 겹쳐도 안전하다

## 6. 시간 처리 (⭐ 사고 다발 지점)

| 규칙 | 내용 |
|---|---|
| 기준 시각 | **항상 서버 시간.** 클라이언트가 보낸 시각을 신뢰하지 않는다 |
| 타임존 | ⛔ **`TZ` 환경변수에 기대지 않는다.** Vercel 함수는 UTC로 돈다 |
| 라이브러리 | **Luxon `DateTime` 만 사용.** raw `Date` 산술 금지 |
| 클라 타이머 | **표시 전용.** 재진입·포커스 복귀 시 서버와 재동기화 |
| 현재 시각 주입 | `now: DateTime`을 인자로 받는다 (§2.1) |

### 6.1 프로세스 TZ 고정이 불가능해진 대가 ⭐

v1.0~v2.0의 1번 방어선은 *"프로세스 타임존을 `Asia/Seoul`로 고정한다"* 였다.
**서버리스에서는 이걸 보장할 수 없다.** 그래서 방어를 환경에서 **코드로 끌어내린다.**

```ts
// packages/domain/time/zone.ts — zone 을 아는 유일한 곳
export const APP_ZONE = 'Asia/Seoul';

export function nowInAppZone(): DateTime {
    return DateTime.now().setZone(APP_ZONE);
}

export function workDateOf(instant: DateTime): string {
    // 반드시 존을 옮긴 뒤 날짜를 뽑는다. UTC 15:30 은 KST 로 '다음 날'이다
    return instant.setZone(APP_ZONE).toFormat('yyyy-MM-dd');
}
```

```ts
// ✗ 절대 금지 — 하루가 통째로 밀린다
const workDate = new Date(dateString);                            // UTC 자정으로 파싱된다
const tomorrow = new Date(now.getTime() + 24 * 60 * 60 * 1000);   // DST/윤초 무시
const today = DateTime.now();                                     // 존이 UTC 다

// ✓
const workDate = DateTime.fromISO(dateString, { zone: APP_ZONE }).startOf('day');
const tomorrow = nowInAppZone().plus({ days: 1 });
```

| 방어선 | 수단 |
|---|---|
| 1 | `packages/domain/time`이 **존을 아는 유일한 곳.** 다른 파일에 `'Asia/Seoul'` 문자열이 나오면 리뷰에서 막는다 |
| 2 | ESLint `no-restricted-globals`로 `Date` 직접 사용 차단 · `no-restricted-syntax`로 `DateTime.now()` 직접 호출 차단 |
| 3 | Prisma `DATE` 컬럼은 `@db.Date` (`02-데이터모델.md` 표기 규칙) |
| 4 | 타임존 테스트 4건 (`../테스트/01-테스트계획.md` §6) — **CI를 `TZ=UTC`로 돌린다.** 이게 운영과 같은 조건이다 |

> 4번이 v2.0에서 뒤집혔다. 예전엔 *"`TZ=UTC`로 띄우면 실패해야 한다"* 였지만,
> 이제 **UTC가 운영 환경이므로 `TZ=UTC`에서 전부 통과해야 한다.**
> 결과적으로 더 강한 테스트다 — 환경이 아니라 코드가 옳다는 걸 증명한다.

## 7. Prisma × 서버리스 (⭐ N-022)

함수 호출마다 커넥션을 새로 잡으면 Postgres 한도에 금방 닿는다. **잘 돌다가 갑자기 터진다.**

### 7.1 URL 이 둘로 갈린다 (⚠️ Prisma 7 · N-025)

Prisma 7에서 **`datasource.directUrl` 은 없어졌다.** 스키마에는 URL 자체를 쓰지 않는다.
`prisma.config.ts` 의 `datasource` 는 **CLI 전용**이고(migrate · db pull · studio),
런타임은 앱이 **드라이버 어댑터**로 직접 연결한다. 그래서 URL 이 자연스럽게 둘로 갈린다.

| 용도 | 값 | 어디서 읽나 |
|---|---|---|
| 마이그레이션 | `DIRECT_URL` (5432 직결) | `packages/db/prisma.config.ts` |
| 런타임 | `DATABASE_URL` (6543 풀러 + `connection_limit=1`) | `apps/web/src/server/prisma.ts` |

```prisma
// packages/db/prisma/schema.prisma — url 이 없다
generator client {
  provider = "prisma-client"        // ⚠️ prisma-client-js 아님
  output   = "../generated/prisma"  // ⚠️ 필수
}
datasource db {
  provider = "postgresql"
}
```

```ts
// packages/db/prisma.config.ts — CLI 가 쓰는 URL
export default defineConfig({
    schema: 'prisma/schema.prisma',
    migrations: { path: 'prisma/migrations' },
    datasource: {
        url: process.env['DIRECT_URL'],
        shadowDatabaseUrl: process.env['SHADOW_DATABASE_URL'],
    },
});
```

```ts
// apps/web/src/server/prisma.ts — 런타임 싱글턴
import 'server-only';
import { PrismaClient, PrismaPg } from '@nfs/db';

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };

function createPrismaClient(): PrismaClient {
    const adapter = new PrismaPg({ connectionString: process.env['DATABASE_URL'] });
    return new PrismaClient({ adapter });
}

// 개발 모드의 핫 리로드가 매번 새 클라이언트를 만들어 커넥션을 소진하는 걸 막는다
export const prisma = globalForPrisma.prisma ?? createPrismaClient();
if (process.env.NODE_ENV !== 'production') {
    globalForPrisma.prisma = prisma;
}
```

| 함정 | 대응 |
|---|---|
| 핸들러 안에서 `new PrismaClient()` | 호출마다 커넥션이 는다. **모듈 스코프 싱글턴만** |
| 풀러로 마이그레이션 시도 | pgBouncer는 준비된 구문을 지원하지 않아 실패한다. `DIRECT_URL` 필수 |
| 생성물을 커밋 | 스키마와 어긋난 채 굳는다. `generated/` 는 ignore하고 **루트 `postinstall`이 `prisma generate`** 를 돌린다 |
| `migrate dev` 후 타입이 안 맞음 | Prisma 7은 **generate를 자동 실행하지 않는다.** 따로 부른다 |
| Supabase 무료 프로젝트 일시정지 | 매일 도는 배치 크론이 자연히 막아준다 (N-022) |

### 7.2 DATE 컬럼 변환 규약 ⭐

`work_date` · `stat_date` · `week_start_date` 는 도메인에서 `'yyyy-MM-dd'` 문자열이지만,
드라이버를 거치면 **JS `Date`** 가 된다. **여기가 하루 밀리는 자리다.**

```
'2026-08-19' 를 한국 시간 0시로 만들면 → UTC 2026-08-18T15:00 → DATE 컬럼에서 8월 18일로 잘린다
```

**규약: DATE 컬럼은 "그 날짜의 UTC 자정"으로만 표현한다.** 타임존 변환을 하지 않는다 —
애초에 시각이 아니라 달력 위의 한 칸이기 때문이다.

`packages/domain/time/date-column.ts` 가 이 변환의 **유일한 출구**다
(`dateStringToDateColumn` · `dateColumnToDateString` · `instantToDateColumn`).
저장소 계층에서만 쓰고, 서비스와 화면은 문자열만 본다.

## 8. 예외 · 응답 규약

응답 형식과 에러 코드는 **v1.0에서 한 글자도 바뀌지 않았다.** REST 계약은 스택과 무관하다.

```json
// 성공
{ "success": true, "data": { ... } }

// 실패
{ "success": false, "error": { "code": "BUDGET_EXCEEDED", "message": "오늘 남은 4시간을 넘습니다", "detail": { "remainingMinutes": 240 } } }
```

| 코드 | 상황 | HTTP |
|---|---|---|
| `BUDGET_EXCEEDED` | 24시간 예산 초과 | 400 |
| `INVALID_BLOCK_LENGTH` | 30분 배수 아님 | 400 |
| `CATEGORY_REQUIRED` | 태그 미지정 | 400 |
| `ILLEGAL_BLOCK_STATE` | 잘못된 상태 전이 | 409 |
| `ALREADY_SETTLED` | 이미 정산됨 | 409 |
| `CALENDAR_SYNC_FAILED` | 구글 호출 실패 | 502 |
| `WEEK_ALREADY_CLOSED` | 마감된 주 수정 시도 | 409 |

구현은 `src/server/http/` 의 **`withMember` 래퍼 한 곳**에서 처리한다 (§3.1).
도메인 예외(`NfsError`)를 잡아 위 표대로 코드·상태를 매핑하고, 그 외 예외는 **500 + 로그**로 떨어뜨린다.
**`message`는 사용자에게 그대로 보여줄 수 있는 한국어**로 쓴다. 프론트에서 코드별 문구를 다시 만들지 않는다.

## 9. 보안

| 항목 | 처리 |
|---|---|
| 세션 | **httpOnly 쿠키.** `SameSite=Lax` · `Secure` · 동일 출처라 CORS 불필요 |
| 구글 리프레시 토큰 | **DB에 암호화 저장.** 브라우저로 절대 내려보내지 않는다. 연동 해제 시 즉시 파기 |
| 스코프 | 기본 읽기 전용. 쓰기는 증분 권한 요청 (Phase 2) |
| 배치 엔드포인트 | `x-cron-secret` 불일치 시 **404** (§5.1) |
| XSS | React가 기본 이스케이프. **`dangerouslySetInnerHTML` 금지** (블록 제목·캘린더 일정 제목) |
| CSRF | 쿠키 세션이므로 상태 변경 API에 토큰 필수. `SameSite=Lax`만 믿지 않는다 |
| 인가 | 모든 조회/변경에 `memberId` 조건 강제. **URL의 id를 신뢰하지 않는다** |
| 서버/클라 경계 | `import 'server-only'` (§2.2). **커넥션 문자열이 번들에 섞이는 걸 빌드가 막는다** |
| 환경변수 | `NEXT_PUBLIC_` 접두사만 브라우저로 나간다 — **여기에 시크릿 금지** |

## 10. 배포 체크리스트

### 최초 1회

1. Supabase 프로젝트 생성 → `DATABASE_URL`(6543, `pgbouncer=true&connection_limit=1`) · `DIRECT_URL`(5432) 확보
2. Vercel 프로젝트 연결 · **루트 디렉터리 `apps/web`** · 빌드 커맨드에 `prisma generate` 포함
3. `pnpm prisma migrate deploy` (로컬에서 `DIRECT_URL`로)
4. 구글 OAuth 리다이렉트 URI에 Vercel 도메인 등록
5. `CRON_SECRET` 생성 → **Vercel 환경변수 + GitHub Secrets 양쪽에 같은 값**
6. GitHub Secrets에 `APP_URL` 등록

### 매 배포

1. ⭐ 크론 표현식의 **UTC↔KST 환산 주석**이 시각과 맞는지 (§5)
2. `prisma migrate deploy` 성공 — ⛔ **운영에서 `migrate dev` 금지** (데이터가 날아간다)
3. `app/layout.tsx` 의 `dynamic = 'force-dynamic'` 이 살아 있는지 — 빌드 로그의 모든 라우트가 `ƒ (Dynamic)` 이어야 한다. `○ (Static)` 이 하나라도 보이면 그 화면은 날짜가 박제된다
4. `NEXT_PUBLIC_*` 에 시크릿이 섞여 있지 않은지
5. `workflow_dispatch`로 배치 두 개를 **손으로 한 번 돌려본다.** 크론을 하루 기다려 확인하지 않는다
