## 1. Supabase 프로젝트 만들기

### 1.1 생성

1. https://supabase.com → **Start your project** → GitHub 로 로그인
2. **New project**
   - **Name**: `nfs`
   - **Database Password**: ⚠️ **강한 비밀번호를 만들고 즉시 안전한 곳에 저장한다.**
     이 값은 나중에 다시 볼 수 없고, 커넥션 문자열에 그대로 들어간다
   - **Region**: **Northeast Asia (Seoul)** — `ap-northeast-2`
   - **Plan**: Free

> ⚠️ **리전을 서울로 고른다.** Vercel 함수와 DB 가 멀면 쿼리마다 왕복 지연이 붙는다.
> 무료 티어에서 가장 체감되는 성능 차이가 여기서 난다.

프로비저닝에 1~2분 걸린다.

### 1.2 커넥션 문자열 두 개 가져오기 ⭐

**Project Settings → Database → Connection string** 에서 두 가지를 챙긴다.
**둘 다 필요하다. 하나로 퉁치면 반드시 터진다.**

| 용도 | 탭 / 포트 | 환경변수 |
|---|---|---|
| **런타임** (앱이 쿼리할 때) | **Transaction pooler** · `6543` | `DATABASE_URL` |
| **마이그레이션** (스키마 변경) | **Session pooler** 또는 Direct · `5432` | `DIRECT_URL` |

런타임 URL 끝에 **파라미터를 반드시 붙인다:**

```
?pgbouncer=true&connection_limit=1
```

완성 예시 (`YOUR-PASSWORD` 와 프로젝트 ref 는 본인 것으로):

```
DATABASE_URL="postgresql://postgres.abcdefgh:YOUR-PASSWORD@aws-0-ap-northeast-2.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1"
DIRECT_URL="postgresql://postgres.abcdefgh:YOUR-PASSWORD@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres"
```

> **왜 두 개인가** (아키텍처 §7.1)
> - **런타임에 풀러가 필요한 이유:** 서버리스는 함수 호출마다 커넥션을 새로 잡는다. 직결로 쓰면 Postgres 커넥션 한도에 금방 닿아 **잘 돌다가 갑자기 터진다.** `connection_limit=1` 은 함수 인스턴스 하나가 커넥션 하나만 쥐게 한다
> - **마이그레이션에 직결이 필요한 이유:** pgBouncer 는 준비된 구문(prepared statement)을 지원하지 않아 `prisma migrate` 가 실패한다
> - Prisma 6까지 있던 `datasource.directUrl` 은 **7에서 없어졌다.** 그래서 파일이 갈린다 (N-025)

### 1.3 로컬 `.env.local` 작성

저장소 루트에서:

```bash
cp .env.example .env.local
```

`.env.local` 을 열어 위 두 값을 채운다. **나머지는 아직 비워둬도 된다.**

> ⚠️ `.env.local` 은 `.gitignore` 가 막고 있다. 커밋되지 않는다.
> **비밀번호가 들어 있으니 채팅·이슈·PR 에 붙여넣지 않는다.**

**확인**
```bash
grep -c "postgresql://" .env.local     # 2 가 나와야 한다
```

### 1.4 스키마 올리기 ⭐

```bash
pnpm --filter @nfs/db exec prisma migrate deploy
```

`migrate deploy` 는 이미 커밋된 마이그레이션(`20260819000000_init`)을 그대로 적용한다.

> ⛔ **운영 DB 에 `migrate dev` 를 쓰지 않는다.** 드리프트를 감지하면 DB 를 리셋한다.
> 지금은 데이터가 없어 상관없지만, 습관이 남으면 나중에 원장을 날린다.

**확인**
```bash
pnpm --filter @nfs/db exec prisma migrate status
```
`Database schema is up to date!` 가 나와야 한다.

Supabase 대시보드 **Table Editor** 에서도 테이블 6개가 보인다:
`member` · `active_block` · `imported_calendar_event` · `time_log` · `weekly_closing` · `category_color_mapping`

## 2. 구글 OAuth 클라이언트

로그인과 캘린더 읽기가 이 하나를 같이 쓴다 (N-014).

### 2.1 프로젝트 · API 활성화

1. https://console.cloud.google.com → 프로젝트 만들기 (`NFS`)
2. **API 및 서비스 → 라이브러리** → **Google Calendar API** 검색 → **사용**

### 2.2 동의 화면

**API 및 서비스 → OAuth 동의 화면**

| 항목 | 값 |
|---|---|
| User Type | **외부** |
| 앱 이름 | `NFS — Not For Sale` |
| 사용자 지원 이메일 | 본인 |
| 범위(Scopes) | `.../auth/userinfo.email` · `.../auth/userinfo.profile` · **`.../auth/calendar.readonly`** |
| 테스트 사용자 | 본인 계정 추가 |

> **읽기 전용 스코프로 시작한다** (N-014). 쓰기 권한은 가입 퍼널을 누르므로 Phase 2 에서 증분 요청한다.
> 게시 상태는 **테스트**로 둔다. 본인만 쓸 거라면 심사가 필요 없다.

### 2.3 클라이언트 ID

**사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**

- 유형: **웹 애플리케이션**
- **승인된 리디렉션 URI** — 지금은 로컬 것만 넣는다:
  ```
  http://localhost:3000/api/auth/google/callback
  ```
  운영 도메인은 **4.3 에서 추가한다** (Vercel 도메인이 아직 없다)

발급된 **클라이언트 ID / 보안 비밀**을 `.env.local` 에 넣는다:

```
GOOGLE_CLIENT_ID="....apps.googleusercontent.com"
GOOGLE_CLIENT_SECRET="GOCSPX-..."
```

## 4. Vercel 배포

### 4.1 프로젝트 연결

1. https://vercel.com → GitHub 로 로그인 → **Add New → Project**
2. `you4ranghe/nfs` **Import**
3. ⭐ **설정을 바꿔야 한다. 기본값으로 두면 빌드가 깨진다** — 모노레포이기 때문이다

| 항목 | 값 |
|---|---|
| **Root Directory** | **`apps/web`** ← 반드시 바꾼다 |
| Framework Preset | Next.js (자동) |
| Build Command | 비워둔다 (기본값) |
| Install Command | 비워둔다 (기본값) |

> **왜 Root Directory 가 `apps/web` 인가:** Vercel 이 Next.js 앱을 찾아야 한다.
> 저장소 루트에는 `next.config.ts` 가 없다.
>
> Vercel 은 `apps/web` 을 루트로 잡아도 **워크스페이스 전체를 설치한다** (pnpm workspace 를 인식한다).
> 그래서 `@nfs/domain` · `@nfs/db` 가 정상적으로 링크되고, 루트 `postinstall` 이
> `prisma generate` 를 돌려 클라이언트 타입까지 만들어준다.

### 4.2 환경변수

**Deploy 를 누르기 전에** Environment Variables 에 다섯 개를 넣는다.
(Production · Preview · Development 전부 체크)

| 이름 | 값 |
|---|---|
| `DATABASE_URL` | 풀러 6543 URL (`?pgbouncer=true&connection_limit=1` 포함) |
| `DIRECT_URL` | 직결 5432 URL |
| `GOOGLE_CLIENT_ID` | 2.3 에서 발급 |
| `GOOGLE_CLIENT_SECRET` | 2.3 에서 발급 |
| `SESSION_SECRET` | 3장에서 생성 |
| `CRON_SECRET` | 3장에서 생성 |

> ⚠️ **`NEXT_PUBLIC_` 접두사를 붙이지 않는다.** 그 접두사가 붙은 값만 브라우저 번들로 나간다.
> 시크릿에 붙이면 누구나 개발자 도구에서 볼 수 있다.

**Deploy** 를 누른다. 2~3분.

**확인**
- 배포된 URL 에서 리포트 화면이 뜨고 하단 탭이 보인다
- 빌드 로그의 Route 표에 **모든 라우트가 `ƒ (Dynamic)`** 이다
  → `○ (Static)` 이 하나라도 보이면 그 화면은 빌드 시점 날짜가 박제된다 (N-024)

### 4.3 구글 리디렉션 URI 추가 (잊기 쉬움)

Vercel 도메인이 생겼으니 구글 콘솔로 돌아가 **승인된 리디렉션 URI** 에 추가한다:

```
https://<프로젝트>.vercel.app/api/auth/google/callback
```

> 이걸 빼먹으면 배포본에서 로그인 버튼을 눌렀을 때 `redirect_uri_mismatch` 가 난다.
> **로컬은 되는데 배포본만 안 되는** 가장 흔한 원인이다.

## 5. GitHub Actions 크론 (배치)

Vercel 은 서버리스라 **상주 프로세스가 없다.** `@Cron` 같은 스케줄러가 돌지 않는다.
그래서 배치를 밖에서 밀어 넣는다 (N-022).

### 5.1 GitHub Secrets

저장소 **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `CRON_SECRET` | ⭐ **Vercel 에 넣은 것과 같은 값** |
| `APP_URL` | `https://<프로젝트>.vercel.app` (끝에 `/` 없이) |

### 5.2 워크플로

`.github/workflows/` 는 **O-07 에서 커밋한다.** 시각은 이렇게 정해져 있다:

| 잡 | KST | UTC 크론 |
|---|---|---|
| 자정 정산 | 매일 **00:05** | `5 15 * * *` |
| 주간 마감 | **월** 04:00 | `0 19 * * 0` ← **일요일** |

> ⚠️ **주간 마감이 크론에서 일요일인 이유:** KST 월요일 04:00 = **UTC 일요일 19:00**.
> 9시간 차이가 **요일까지** 밀어버린다. 이 프로젝트가 반복해서 밟는 함정이 인프라 레벨에서 다시 나타난 것이다.
> 크론 표현식 옆에 KST 환산을 **반드시 주석으로 병기한다.**

### 5.3 확인

크론을 하루 기다려 확인하지 않는다. 워크플로에 `workflow_dispatch` 를 넣어두고
**Actions 탭에서 손으로 한 번 돌린다.**

## 6. 무료 티어에서 알아둘 것

| 항목 | 내용 | 대응 |
|---|---|---|
| Supabase 프로젝트 일시정지 | 일정 기간 비활성이면 멈춘다 | 매일 도는 배치 크론이 자연히 막아준다 |
| Vercel 함수 실행시간 상한 | 배치가 한 번에 다 못 돌 수 있다 | 응답에 `hasMore` 를 담고 워크플로가 재호출한다 (아키텍처 §5.2) |
| 콜드스타트 | 첫 요청이 느리다 | 검증 단계에선 받아들인다 |
| DB 용량 500MB | `time_log` 만 무한히 는다 | 한참 뒤 이야기다. 연도별 아카이빙은 그때 검토 |

**이건 "테스트 배포" 결정이다** (N-022). 다만 **Postgres 전환과 배치 외부화는 되돌리지 않는다** —
둘 다 EC2 로 옮겨가도 그대로 유효하고, 오히려 이식성이 높다.

## 7. 막혔을 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 빌드 시 `next.config not found` | Root Directory 가 저장소 루트다 | `apps/web` 으로 바꾼다 (4.1) |
| 빌드 시 Prisma 타입 오류 | `prisma generate` 가 안 돌았다 | 루트 `postinstall` 이 있는지 확인. 없으면 Build Command 를 `pnpm --filter @nfs/db generate && next build` 로 |
| `migrate` 가 멈추거나 실패 | 풀러(6543)로 마이그레이션했다 | `DIRECT_URL`(5432)을 쓴다 (1.2) |
| 런타임에 커넥션 오류가 산발적 | 풀러/`connection_limit` 누락 | `DATABASE_URL` 에 `?pgbouncer=true&connection_limit=1` (1.2) |
| `redirect_uri_mismatch` | 운영 도메인을 구글에 등록 안 했다 | 4.3 |
| 배치가 안 돈다 (로그도 없다) | `CRON_SECRET` 불일치 → **404** | Vercel 과 GitHub Secrets 값을 맞춘다 (5.1) |
| 배치가 9시간/하루 어긋난다 | 크론을 KST 로 썼다 | UTC 로 환산한다 (5.2) |
| 날짜가 하루 밀린다 | 코드에서 존을 안 붙였다 | `packages/domain/time` 만 쓴다. ESLint 가 막고 있다 |
