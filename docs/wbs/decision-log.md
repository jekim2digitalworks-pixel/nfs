### N-003 · 구글 캘린더는 "단방향 파이프 두 개"로 설계
📅 2026-08-18 · 개발

구글 캘린더 API는 읽기·쓰기 모두 가능하지만, 하나의 양방향 동기화로 만들면 **에코 루프**에 빠진다. 우리가 쓴 일정을 다시 읽어 통계에 이중 반영되고 24시간 예산도 우리가 쓴 것 때문에 우리가 잠긴다.

- 읽기: 구글 → NFS (열린 주만, 마감되면 중단)
- 쓰기: NFS → 구글 (완료 블록만, 옵트인)
- 차단막: `extendedProperties.private`에 NFS 블록 ID를 심고, 읽을 때 건너뜀

**버린 것:** 단일 양방향 동기화

### N-004 · 주간 마감 후 캘린더 재조회 금지
📅 2026-08-18 · 기획

성능이 아니라 **통계 재현성** 때문이다. 매번 재조회하면 사용자가 지난달 일정 제목 하나만 고쳐도 *지난달 리포트가 지난주에 본 것과 달라진다.* 가계부에서 숫자가 흔들리면 회고 기능의 존재 이유가 사라진다.
부수 효과로 토큰 만료·연동 해제 후에도 과거 통계가 보존되고, API 호출량이 누적 기간에 비례하지 않는다.

**예외 1건:** 가입 시 최근 4~8주 백필 (빈 화면 이탈 방지)
**마감 시각:** 월요일 04:00 (일요일 밤 작업자에게 유예)

### N-005 · 24시간 하드캡 + 합집합 계산
📅 2026-08-18 · 기획

단순 합산(캘린더 20h + 블록 4h = 24h)으로 하면 **이중 예약이 잦은 사용자가 앱을 아예 못 쓴다.** 캘린더만으로 예산을 다 태워버리기 때문이다. 정작 이 앱이 가장 필요한 사람이 차단된다.

규칙 4줄:
1. 배치는 자유 (겹치는 자리에도 블록 생성 가능 — 구글 가서 고치라고 요구하지 않는다)
2. 계산은 합집합 (같은 시각은 몇 개가 겹치든 1분은 1분)
3. 상한은 1440분
4. 귀속은 실측 우선 (겹친 구간의 태그는 타이머가 돈 블록의 것)

**버린 것:** 총합(gross) 방식

### N-006 · 실측과 신고를 합산하지 않고 두 축으로 표시
📅 2026-08-18 · 기획

### N-007 · 가변 작업 영역과 불변 원장을 물리적으로 분리
📅 2026-08-18 · 개발

`ActiveBlock`·`ImportedCalendarEvent`(가변, 잦은 CUD)와 `TimeLog`(불변, append-only, 읽기 전용)를 다른 테이블로 둔다. 사실상 **CQRS의 가장 가벼운 형태**다.

- 통계용 복합 인덱스가 UPDATE 비용을 물지 않는다
- 통계 쿼리에 `where status='COMPLETED'` 가 영원히 따라붙는 일이 없다 — *존재 자체가 확정의 증거*
- 진행 중에만 의미 있는 컬럼과 완료 후에만 의미 있는 컬럼이 서로를 오염시키지 않는다

**대가:** 이관 트랜잭션이 새 실패 지점이 된다 → `(member_id, source_type, source_reference_key)` UNIQUE로 멱등성 확보

### N-013 · 깊이 줌을 MVP에서 제외 (Q-002 해소) ⭐
📅 2026-08-18 · 기획 · 개발

**N-001/N-002와 확정 시안의 불일치를 정리한다.**
N-001에서 "3화면 슬라이드 대신 깊이축 통합"을 택하고 N-002에서 TS 카메라 번들 예외를 허용했으나,
확정된 시안 A/B/C는 **떠 있는 탭으로 화면을 전환**하고 줌 제스처를 쓰지 않는다.

**결정:** MVP는 **탭 내비게이션만**. 깊이 줌은 Phase 2.

근거 — 줌은 *제품을 특별하게* 만들지만 *제품을 성립시키지는* 않는다.
MVP에 넣으면 **가장 어려운 것이 가장 먼저** 오고, TS 빌드 파이프라인까지 크리티컬 패스에 들어온다.
탭으로 먼저 출시해 사용자가 실제로 화면 사이를 얼마나 오가는지 본 뒤 얹는 것이 순서다.

**따라오는 결과**
- 프론트는 **순수 JSP + jQuery.** TS 번들 파이프라인을 O-02 스캐폴딩에 넣지 않는다
- **N-002(TS 번들 예외)는 MVP에서 보류.** Phase 5 착수 시 되살린다
- **N-001은 폐기가 아니라 이연.** 깊이축 개념은 유효하며 Phase 5에서 구현한다
- `cal_bak`은 **참조만 한다.** 코드를 복사하지 않으므로 라이선스·이력 정리는 Phase 5로 미룬다

**버린 것:** MVP 단계의 시각적 차별점
