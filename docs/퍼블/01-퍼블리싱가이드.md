### 1.1 스타일링 방식 — 왜 CSS Modules / Tailwind 가 아닌가

**플레인 CSS + 전역 클래스**로 간다. 확정 시안 A/B/C가 이미 이 방식으로 쓰여 있고,
`--dev`·`--meet` 같은 카테고리 토큰을 `color-mix()`로 조합하는 패턴이 시안의 핵심이기 때문이다.

| 후보 | 왜 안 골랐나 |
|---|---|
| Tailwind | 토큰이 유틸 클래스로 흩어져 `tokens.css` 단일 원천이 깨진다. 시안 3종을 통째로 번역해야 한다 |
| CSS Modules | 화면 전용 스타일에는 적합하지만, 공통 컴포넌트 토큰까지 지역화하면 `color-mix` 조합이 어려워진다 |
| 결론 | **전역 토큰 + BEM식 클래스.** 화면 전용은 `.screen-day` 루트 스코프로 가둔다 |

## 2. CSS 규칙

### 2.1 선택자

- 클래스 기반. **ID 선택자로 스타일링하지 않는다** (JS 훅으로만 사용)
- 요소 선택자와 클래스 선택자를 섞지 않는다 — 특정도가 서로를 무효화한다

```css
/* ✗ 이런 게 사고를 낸다 */
.section { padding: 20px }
section  { padding: 0 }      /* 어디서 이겼는지 추적 불가 */

/* ✓ */
.section { padding: 20px }
.section--flush { padding: 0 }
```

- 화면 전용 스타일은 루트에 화면 클래스를 걸고 그 안에서만 쓴다

```tsx
// app/day/page.tsx
export default function DayPage() {
  return <main className="screen-day">…</main>;
}
```

### 2.2 값

| 항목 | 규칙 |
|---|---|
| 색 | **반드시 토큰.** 하드코딩된 hex 금지 |
| 간격 | 4의 배수 (예외: 타임라인 `--hr:46px`) |
| 반경 | `--r-xl` / `--r-lg` / `--r-md` / `99px` |
| 카테고리 틴트 | `color-mix(in srgb, var(--c) 36%, transparent)` — 색을 새로 정의하지 않는다 |
| 뷰포트 높이 | **`100dvh`.** `100vh`는 모바일 주소창 때문에 잘린다 |

### 2.3 반드시 지킬 것

```css
/* 하단 탭 — left:50% 는 shrink-to-fit 폭을 절반으로 가둔다. 실제로 라벨이 세로로 깨졌다 */
.tabs{ left:50%; transform:translateX(-50%); width:max-content; }

/* 홈 인디케이터 영역 */
.tabs{ bottom: calc(26px + env(safe-area-inset-bottom)); }

/* 모션 감소 존중 — 호흡·펄스 포함 전부 */
@media (prefers-reduced-motion: reduce){
  *,*::before,*::after{ animation:none !important; transition:none !important }
}
```

## 3. 마크업 규칙

**JSX여도 결과물은 HTML이다.** 시맨틱 기준은 v1.0에서 하나도 완화되지 않는다.

| 항목 | 규칙 |
|---|---|
| 시맨틱 | `header` / `main` / `section` / `nav` 사용. `div` 남용 금지 |
| 버튼 vs 링크 | 동작은 `<button>`, 이동은 `<Link>`. **`<div onClick>` 금지** |
| 차트 | `role="img"` + `aria-label`에 값을 문장으로 |
| 숫자 | 모든 숫자에 `className="num"` (tabular-nums) |
| 라이브 영역 | 타이머는 `aria-live="off"` (매초 읽으면 소음). 상태 변경 시에만 `aria-live="polite"` 로 알림 |
| 포커스 | `:focus-visible`만 스타일. 마우스 클릭에 링이 뜨지 않게 |
| 터치 타겟 | 최소 44×44px |

### 3.1 XSS

사용자 입력이 들어가는 자리는 **블록 제목**과 **캘린더 일정 제목** 두 곳이다.

React는 JSX에 넣은 문자열을 **기본으로 이스케이프**한다. 그러니 규칙은 하나로 줄어든다.

```tsx
// ✓ 그냥 이렇게 쓰면 안전하다
<span className="block-title">{block.title}</span>

// ✗ 금지 — 이 프로젝트에 이게 필요한 자리는 없다
<span dangerouslySetInnerHTML={{ __html: block.title }} />
```

> ESLint `react/no-danger`를 **error**로 켠다. 규칙은 사람이 기억하는 게 아니라 도구가 막는 것이다.

### 3.2 Server Component / Client Component 경계

| 이것은 | 어디에 |
|---|---|
| 첫 렌더 데이터 조회 (리포트 총계, 하루 예산) | **Server Component** — ⭐ **서비스 함수를 직접 부른다.** 자기 API를 fetch 하지 않는다 |
| 타이머 · 시트 열림 · 핀치 · 토스트 | **Client Component** (`'use client'`) |

```tsx
// ✓ 같은 프로세스다. HTTP 를 한 바퀴 도는 건 순수한 낭비다
import { getDaySummary } from '@/server/services/day';
export default async function DayPage() {
  const summary = await getDaySummary(memberId, today);
  return <DayScreen summary={summary} />;
}

// ✗ 자기 자신에게 fetch — 절대 URL 도 필요해지고, 쿠키를 손으로 전달해야 한다
const summary = await fetch(`${origin}/api/day`).then(r => r.json());
```

**첫 화면을 클라이언트에서 다시 불러오지 않는다.** 스켈레톤이 깜빡이고 체감 속도가 나빠진다.
(v1.0의 *"첫 화면을 Ajax로 다시 부르지 않는다"* 와 같은 원칙 — 수단만 JSP 모델에서 RSC로 바뀌었다.)

⚠️ `'use client'`를 페이지 최상단에 붙이면 그 아래 전부가 클라이언트가 된다.
**경계는 가능한 한 잎사귀 쪽으로 민다.** 타이머 하나 때문에 집중 화면 전체가 클라이언트가 될 이유는 없다.

## 4. TS / React 규칙

### 4.1 API 레이어 (`lib/api.ts`)

모든 통신은 이 레이어를 통한다. 화면 코드에서 `fetch`를 직접 부르지 않는다.

**API가 같은 앱에 있으므로 동일 출처다** (N-023). 절대 URL도, CORS 설정도, `credentials: 'include'`도 필요 없다 —
세션 쿠키가 그냥 붙는다.

```ts
// 서버 응답 규약: { success, data } | { success, error: { code, message, detail } }
// 단계가 보이게 쓴다 (CLAUDE.md §3)
export async function postJson<T>(path: string, payload: unknown): Promise<T> {
    const response = await fetch(path, {          // 동일 출처 — 상대 경로면 충분하다
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(payload),
    });
    const body = await response.json();

    if (body.success === false) {
        // error.message 는 사용자에게 그대로 보여줄 수 있는 한국어다.
        // 프론트에서 코드별 문구를 다시 만들지 않는다.
        throw new NfsApiError(body.error.code, body.error.message, body.error.detail);
    }
    return body.data as T;
}
```

에러 코드별 **추가 동작**만 화면에서 분기한다.
예: `BUDGET_EXCEEDED` → `error.detail.occupiedBy`로 점유 내역 시트를 연다.

### 4.2 타이머 (`hooks/useServerClock.ts`) ⭐

**이 프로젝트에서 가장 많이 틀리는 부분이다. 원칙은 v1.0과 동일하다.**

```
원칙
1. 클라이언트 타이머는 '표시 전용'이다. 정산은 서버가 한다.
2. 경과 시간을 setInterval 로 누적하지 않는다.
   → 탭이 백그라운드로 가면 브라우저가 타이머를 조인다. 값이 조용히 뒤처진다.
3. 서버가 준 기준 시각과 로컬 시각의 차이(offset)를 저장하고,
   매 틱마다 (Date.now() + offset) 으로 '지금'을 다시 계산한다.
4. visibilitychange 로 화면이 돌아오면 즉시 서버와 재동기화한다.
```

```ts
'use client';

export function useServerClock() {
    // 렌더와 무관한 값이라 state 가 아니라 ref 에 둔다.
    // state 로 두면 offset 이 바뀔 때마다 트리 전체가 다시 그려진다.
    const serverOffsetMillis = useRef(0);

    function syncWithServer(serverTimeIso: string): void {
        const serverTime = new Date(serverTimeIso).getTime();
        const localTime = Date.now();
        serverOffsetMillis.current = serverTime - localTime;
    }

    function currentServerTime(): number {
        return Date.now() + serverOffsetMillis.current;
    }

    useEffect(() => {
        function handleVisibilityChange(): void {
            if (document.hidden) {
                return;
            }
            getJson('/api/blocks/current').then((data) => {
                if (data !== null) {
                    syncWithServer(data.serverTime);
                }
            });
        }
        document.addEventListener('visibilitychange', handleVisibilityChange);
        return () => document.removeEventListener('visibilitychange', handleVisibilityChange);
    }, []);

    return { syncWithServer, currentServerTime };
}
```

> `document.hidden` 상태에서 잰 값은 거짓이다. 참조 프로젝트 `cal_bak`이 한 세션에서 세 번 밟은 함정이고,
> **타이머 앱인 NFS는 훨씬 자주 밟는다.**

⚠️ **React 18 StrictMode는 개발 모드에서 effect를 두 번 실행한다.** 동기화 요청이 두 번 나가는 걸 보고
"버그"라고 착각하지 않는다. 대신 **cleanup을 반드시 반환**해서 리스너가 중복 등록되지 않게 한다 (위 코드의 `return`).

### 4.3 차트 (`components/chart/`)

라이브러리를 쓰지 않는다. 필요한 건 세 가지뿐이고 전부 인라인 SVG/CSS로 만든다.

| 차트 | 방법 |
|---|---|
| 링 | SVG `circle` + `strokeDasharray` / `strokeDashoffset` 누적 |
| 캡슐 미터 | flex + `border-radius:99px` 세그먼트 |
| 타임라인 | 절대 배치. `top = (분 − 시작분) × (--hr / 60)` |

**타임라인 좌표는 서버가 준 분 값으로 계산한다.** 시안 작업 중 실제로
`10:00–11:30`(90분)을 150분으로 계산해 블록이 2.5시간짜리로 그려진 사고가 있었다.
헬퍼 하나로 고정한다.

```ts
export function minutesToPixels(minutes: number): number {
    return minutes * (HOUR_HEIGHT_PX / 60);
}
```

### 4.4 Hydration 불일치 ⭐ (Next.js 신규 함정)

**서버에서 그린 HTML과 클라이언트 첫 렌더가 다르면 React가 경고를 뱉고 화면이 한 번 튄다.**
시간이 핵심인 이 앱에서 이건 거의 확정적으로 밟는다.

```tsx
// ✗ 서버가 그린 "14:07"과 클라이언트가 그린 "14:08"이 다르다
<span>{new Date().toLocaleTimeString()}</span>

// ✓ '지금'에 의존하는 표시는 마운트 후에만 그린다
const [mounted, setMounted] = useState(false);
useEffect(() => setMounted(true), []);
return <span className="num">{mounted ? formatClock(currentServerTime()) : '--:--'}</span>;
```

| 대상 | 처리 |
|---|---|
| 진행 중 블록의 경과 시간 | 마운트 후 렌더 (위 패턴) |
| 「자정까지 N분」 | 마운트 후 렌더 |
| 리포트 총계 · 태그별 합계 | **서버 렌더 OK** — '지금'에 의존하지 않는다 |
